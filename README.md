# Sori · 소리

내 음악을 **원본 그대로** 스트리밍하는 셀프호스팅 플레이어. 룬(Roon)처럼 표지가 화면의 주인공이고,
음질이 어디서 어떻게 바뀌는지 숨기지 않습니다. 구독료도, 계정도, 광고도 없습니다.

- **비트퍼펙트 전송.** 서버는 디스크의 FLAC·ALAC·WAV·AIFF·MP3 파일을 디코딩도 재압축도 하지 않고 바이트
  그대로 보냅니다. 탐색은 HTTP 범위 요청으로 합니다.
- **신호 경로.** 플레이어의 음질 배지를 누르면 원본 → 서버 → 브라우저 디코더 → 볼륨 → 출력 장치까지 단계마다
  무엇이 일어나는지 펼쳐집니다. 룬과 같은 네 등급(★ 무손실 · ● 고품질 · ● DSP · ● 손실)으로 표시하고,
  출력 장치가 다른 샘플레이트로 열려 있으면 리샘플링된다고 솔직하게 말합니다.
- **브라우저가 못 여는 형식도 재생.** ALAC, AIFF, DSD, WavPack, APE는 서버의 ffmpeg가 FLAC으로 바꿔 흘려 보냅니다.
  ALAC→FLAC은 샘플이 그대로라 여전히 무손실입니다.
- **무료·합법 무손실 스트리밍: 라이브 아카이브.** Internet Archive의 Live Music Archive에서 아티스트가 녹음과
  공유를 허락한 공연 실황을 FLAC 원본으로 바로 재생합니다. 키도 가입도 필요 없습니다.
- **룬 같은 화면.** 표지 색에 물드는 앨범·아티스트 화면, 전체 화면 "지금 재생 중", 대기열 패널(끌어서 순서
  바꾸기), Hi-Res 표시, 장르 모자이크, 키보드 단축키, 모바일 화면.
- **끊김 적은 연속 재생.** 오디오 요소 두 개를 번갈아 쓰며 다음 곡을 미리 받아 둡니다.
- **이어 듣기.** 대기열·위치·볼륨을 기기에 저장하고, 운영체제 미디어 키와 잠금 화면 컨트롤을 지원합니다.

> **왜 "무료 고음질 스트리밍"을 이렇게 만들었나.** 상용 음원을 남의 서버에서 무료로 끌어와 들려주는 서비스는
> 저작권 침해라 만들 수 없습니다. 대신 (1) 이미 가진 음원은 원본 그대로, (2) 공유가 허락된 음원은 무손실로
> — 두 길로 "무료이면서 고음질"을 채웠습니다.

## 바로 해 보기

```bash
npm install
npm run sample        # 시험용 앨범 7장(22곡)을 ./music 에 합성해서 만듭니다. ffmpeg 필요
npm run build
npm start             # http://localhost:3000
```

내 음악을 쓰려면 `MUSIC_DIR`만 가리키면 됩니다. 처음 켤 때 태그와 표지를 읽고, 그다음부터는 바뀐 파일만 다시
읽습니다.

```bash
MUSIC_DIR=/Volumes/Music npm start
```

### 설정 (환경변수)

| 변수            | 기본값    | 뜻                                                                    |
| --------------- | --------- | --------------------------------------------------------------------- |
| `MUSIC_DIR`     | `./music` | 음악 폴더. 읽기만 합니다                                              |
| `DATA_DIR`      | `./.sori` | 색인(`library.json`)과 표지 캐시. 지워도 다시 스캔하면 생깁니다       |
| `SORI_PASSWORD` | (없음)    | 넣으면 비밀번호로 잠급니다. 집 밖에서 열 거라면 꼭 넣으세요           |
| `FFMPEG_PATH`   | `ffmpeg`  | 브라우저가 못 여는 형식을 변환할 때만 씁니다. 없어도 나머지는 됩니다  |
| `PORT`          | `3000`    |                                                                       |

`.env.example`을 `.env.local`로 복사해 써도 됩니다.

### 도커

```bash
docker compose up -d          # docker-compose.yml의 ./music 을 내 음악 폴더로 바꾸세요
```

이미지에는 ffmpeg가 들어 있습니다. 음악 폴더는 읽기 전용으로 붙이고, 색인과 표지는 `sori-data` 볼륨에 남습니다.

## 음질 이야기

### 무엇이 "원본 그대로"인가

서버 → 브라우저 구간은 비트퍼펙트입니다. `/api/stream/<id>`가 보내는 바이트는 파일과 똑같고, 테스트가 이를
해시로 확인합니다. 그 뒤는 브라우저와 운영체제의 몫입니다.

- **브라우저 디코더**는 FLAC을 32비트 부동소수점으로 풉니다. 24비트까지는 손실이 없습니다.
- **볼륨**을 100% 아래로 내리면 디지털 볼륨이라 신호 경로에 `DSP`로 표시됩니다. 앰프나 DAC에서 볼륨을 조절하고
  Sori는 100%에 두면 이 단계가 빠집니다.
- **출력 장치**의 샘플레이트가 곡과 다르면 브라우저가 리샘플링합니다(`고품질`). 96kHz 곡을 비트퍼펙트로 들으려면
  운영체제 출력을 96kHz로 맞추세요 — macOS는 "오디오 MIDI 설정", Windows는 "소리 → 장치 속성 → 고급".

### 형식별로 어떻게 재생되나

| 형식                | 크롬·엣지      | 사파리         | 파이어폭스     |
| ------------------- | -------------- | -------------- | -------------- |
| FLAC, WAV, MP3, AAC | 원본 그대로    | 원본 그대로    | 원본 그대로    |
| ALAC                | FLAC으로 변환  | 원본 그대로    | FLAC으로 변환  |
| AIFF                | FLAC으로 변환  | 원본 그대로    | FLAC으로 변환  |
| DSD, WavPack, APE   | FLAC으로 변환  | FLAC으로 변환  | FLAC으로 변환  |

어느 쪽인지는 브라우저에 직접 물어서(`canPlayType`) 정합니다. 설정 화면에 지금 브라우저의 표가 나옵니다.
변환은 서버에 ffmpeg가 있을 때만 됩니다. DSD는 PCM 24비트/176.4kHz로 바뀝니다.

## 라이브 아카이브

[Live Music Archive](https://archive.org/details/etree)는 녹음을 허락한 밴드(테이퍼 친화 밴드)의 공연 실황 모음입니다.
Sori는 검색과 공연 정보를 archive.org API로 가져오고, 음원은 브라우저가 archive.org에서 직접 받습니다.

- 공연마다 가장 좋은 형식만 고릅니다: 24bit FLAC → FLAC → MP3 → Ogg.
- archive.org는 FLAC의 샘플레이트를 알려 주지 않습니다. 재생을 시작하면 서버가 파일 앞부분만 받아 FLAC 헤더
  (STREAMINFO)를 읽고, 신호 경로에 실제 값을 적습니다.
- 비공개(스트리밍 전용) 파일은 건너뜁니다. 공유 조건은 각 공연 페이지를 따릅니다.

서버가 인터넷에 나갈 수 없으면 이 화면만 안내 문구를 띄우고, 내 라이브러리는 그대로 동작합니다.


### 코드가 어디 있는지

| 파일                                   | 무엇                                                                         |
| -------------------------------------- | ---------------------------------------------------------------------------- |
| `lib/library/scanner.ts`               | 폴더를 걷고 태그를 읽어 색인을 만든다. 바뀐 파일만 다시 읽는다               |
| `lib/library/covers.ts`                | 폴더 그림·박힌 그림 → 480px/1400px WebP, 대표 색                             |
| `lib/library/build.ts`                 | 색인 → 앨범·아티스트·장르, 검색                                              |
| `lib/library/store.ts`                 | 프로세스에 하나뿐인 라이브러리와 스캔 상태                                   |
| `app/api/stream/[id]/route.ts`         | 원본 전송(범위 요청), ffmpeg 변환                                            |
| `lib/player/engine.ts`                 | 오디오 요소 두 개, 미리 받기, 변환 스트림의 탐색                             |
| `lib/player/queue.ts`                  | 대기열 규칙 — 셔플·반복·다음에 재생. React를 모른다                          |
| `lib/player/context.tsx`               | 대기열 상태, 이어 듣기, 미디어 세션                                          |
| `lib/player/signal.ts`                 | 신호 경로 계산                                                               |
| `lib/live/archive.ts`, `lib/live/flac.ts` | archive.org 검색·공연, FLAC 헤더 읽기                                     |
| `app/(main)/…`                         | 화면들. `components/`에 조각들                                               |
| `proxy.ts`                             | `SORI_PASSWORD`가 있을 때만 켜지는 잠금                                      |
| `scripts/make-sample-library.mjs`      | 시험용 앨범 합성. 저작권 걱정 없는 소리                                      |

### 알려진 한계

- 브라우저 재생이라 출력 장치를 독점(Exclusive/Hog) 모드로 열 수 없습니다. 비트퍼펙트로 들으려면 운영체제 출력
  샘플레이트를 곡에 맞춰야 합니다.
- 곡 사이 전환은 미리 받아 둔 오디오 요소로 바꿔 타는 방식이라 거의 이어지지만, 샘플 단위 갭리스는 아닙니다.
- 룬의 멀티룸, DSP 엔진, 스트리밍 서비스(타이달·코부즈) 연동은 없습니다.
- 도커 이미지는 이 저장소의 CI에서 빌드해 보지 않았습니다. 이미지 안에서 실행되는 standalone 서버
  (`SORI_STANDALONE=1 npm run build` → `node .next/standalone/server.js`)는 직접 확인했습니다.
