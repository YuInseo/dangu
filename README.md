# Sori · 소리

내 음악을 **원본 그대로** 듣는 플레이어. 룬(Roon)처럼 표지가 화면의 주인공이고, 음질이 어디서 어떻게 바뀌는지
숨기지 않습니다. 구독료도, 계정도, 광고도 없습니다.

소리 엔진은 러스트로 짠 실행 파일 하나입니다. 같은 엔진이 **안드로이드 앱**, **윈도우 앱**, 그리고 집 서버(리눅스·도커)
안에서 돕니다. 휴대폰 앱은 PC나 서버 없이 **혼자** 휴대폰의 음악 폴더를 읽고 휴대폰의 오디오 장치로 직접 틉니다.
PC·서버와의 연결은 원할 때만 켜는 선택 사항입니다.

- **64비트 엔진, 비트 단위로 검증.** FLAC·ALAC·WAV·AIFF·MP3·AAC·Vorbis를 64비트 부동소수점으로 풉니다. 정수 PCM은
  2의 거듭제곱으로 나눠 옮기므로 한 비트도 잃지 않고, 시험이 ffmpeg로 푼 정수와 비트 단위로 같은지 봅니다.
  DSD64/128은 직접 PCM 176.4kHz로 바꿉니다(30kHz까지 평탄, 60kHz부터 −120dB).
- **샘플 단위 갭리스.** 다음 곡을 미리 열어 두었다가 지금 곡의 마지막 샘플 바로 다음에 붙입니다. 시험: 두 곡을 이어
  튼 출력이 두 파일을 이어 붙인 것과 비트 단위로 같고, 리샘플링할 때도 한 번에 바꾼 것과 1e-12 안에서 같습니다.
- **소리결 DSP (64비트).** 룬의 MUSE처럼 헤드룸, 샘플레이트 변환(카이저 창 다상 필터, 최대 28비트 ≈ 168dB),
  볼륨 레벨링(EBU R128), 크로스피드(bs2b와 같은 식), 파라메트릭·프로시저럴·헤드폰 EQ(AutoEQ 붙여넣기),
  컨볼루션(분할 FFT, 지연 보정), 클리핑 표시기. ffmpeg 없이 엔진이 직접 하고, ffmpeg로 같은 처리를 한 것과
  24비트 1LSB 안에서 같습니다.
- **신호 경로.** 음질 배지를 누르면 원본 → 64비트 → 각 DSP 단계 → 장치까지 단계마다 무엇이 일어나는지 펼쳐집니다.
  룬과 같은 네 등급(보라 별 무손실 · 파랑 별 향상 · 초록 점 고품질 · 노랑 점 저품질)입니다.
- **소리 낼 곳(존).** "이 기기"는 엔진이 기기의 오디오 장치(윈도우 WASAPI, 안드로이드 AAudio)로 직접, 장치가 받는
  가장 정밀한 형식으로 냅니다(정수 형식이면 TPDF 디더). "이 브라우저"는 브라우저가 받아서 틉니다.
- **휴대폰에서도 끝까지.** 화면이 꺼져도 엔진이 대기열을 들고 혼자 이어 틀고, 잠금 화면·알림·헤드셋·블루투스
  단추로 재생/일시정지·다음/이전을 합니다. 전화가 오면 멈췄다가 다시 틀고, 이어폰이 빠지면 멈춥니다.
- **백그라운드 오디오 분석.** 곡마다 라우드니스·트루 피크·파형을 구해 볼륨 레벨링과 파형 진행 막대에 씁니다.
- **무료·합법 무손실 스트리밍: 라이브 아카이브.** Internet Archive의 Live Music Archive에서 밴드가 녹음과 공유를
  허락한 공연 실황을 FLAC 원본으로 받으면서 64비트로 풀어 틉니다. 키도 가입도 필요 없습니다. 아티스트가 내려받기를
  허락한 공연은 링크 하나로 열어 라이브러리에 저장할 수 있습니다.

> **왜 "무료 고음질 스트리밍"을 이렇게 만들었나.** 상용 음원을 남의 서버에서 무료로 끌어와 들려주는 서비스는
> 저작권 침해라 만들 수 없습니다. 대신 (1) 이미 가진 음원은 원본 그대로, (2) 공유가 허락된 음원은 무손실로 —
> 두 길로 "무료이면서 고음질"을 채웠습니다.

## 내려받기

[최신 빌드(sori-latest)](../../releases/tag/sori-latest)는 `sori` 브랜치에 커밋할 때마다 새로 만들어집니다.

| | 파일 | 설치 |
| --- | --- | --- |
| 안드로이드 8 이상 | `Sori-android.apk` | 휴대폰에서 내려받아 엽니다(이 출처의 앱 설치 허용). 처음 열 때 음악 파일·알림 권한을 허락합니다 |
| 윈도우 10/11 | `Sori_*_x64-setup.exe` 또는 `.msi` | 실행해서 설치합니다 |

- 안드로이드는 `내장 저장공간/Music`을, 윈도우는 사용자의 `음악` 폴더를 읽습니다. **설정 → 라이브러리**에서
  바꿀 수 있습니다. 처음 켤 때 태그와 표지를 읽고, 그다음부터는 바뀐 파일만 다시 읽습니다.
- APK는 저장소의 개발용 키(`ci/sori-dev.jks`)로 서명되어 새 빌드를 지우지 않고 덮어 설치할 수 있습니다. 널리
  배포하려면 저장소 비밀값 `SORI_KEYSTORE_BASE64`, `SORI_KEYSTORE_PASS`에 내 키를 넣으세요. CI가 그 키로 서명합니다.
- **자동 업데이트**: 앱은 켜고 조금 뒤와 한 시간마다, 그리고 앱을 다시 열 때 릴리스의 `latest.json`(빌드, 시각, 파일별 SHA-256)을 보고,
  새 빌드가 있으면 뒤에서 미리 받아 둡니다. 아래쪽에 뜨는 **업데이트**(또는 설정 → 정보)를 누르면 윈도우는 설치
  파일이 돌고 앱이 다시 켜지며, 안드로이드는 시스템 설치 창이 뜹니다(처음 한 번 "이 출처의 앱 설치"를 허용).
  같은 커밋이거나 더 옛 빌드로는 가지 않고, 크기나 SHA-256이 다르면 설치하지 않습니다.

## 다른 기기와 잇기 (선택)

휴대폰은 혼자서도 다 됩니다. 원할 때만 **설정 → 연결**에서:

- **이 기기 열기.** "같은 와이파이의 다른 기기에서 열기"를 켜면 LAN 쪽 포트(4390번대)가 하나 더 열리고 6자리
  PIN으로 잠깁니다. 끄면 열려 있던 연결도 바로 끊깁니다. 켜고 끄기와 PIN 보기는 그 기기에서만 됩니다.
- **다른 소리에 연결.** 같은 와이파이의 소리를 찾거나(UDP 방송) 주소로 연결합니다. 화면이 그 소리로 옮겨 가고,
  맨 위에 "○○의 소리에 연결됨 · 이 기기로"가 남습니다. 그 기기의 라이브러리를 이 기기에서 듣거나(이 브라우저),
  그 기기의 스피커로 틉니다.

## 집 서버로 돌리기 (리눅스·도커)

```bash
cargo run --release -p sori-server -- --music /srv/music --data /srv/sori-data     # http://<서버>:4380
docker compose up -d                                                                # docker-compose.yml의 ./music 을 바꾸세요
```

| 변수 / 옵션 | 기본값 | 뜻 |
| --- | --- | --- |
| `SORI_MUSIC_DIR` / `--music` | `./music` | 음악 폴더. 읽기만 합니다 |
| `SORI_DATA_DIR` / `--data` | `./.sori` | 색인, 표지, 분석 결과, 임펄스 응답, 연결 설정. 지워도 다시 만들어집니다 |
| `SORI_HOST` / `--host` | `0.0.0.0` | 처음부터 네트워크에 열립니다(찾기에도 답합니다) |
| `SORI_PORT` / `--port` | `4380` | |
| `SORI_PASSWORD` | (없음) | 넣으면 비밀번호로 잠급니다. 집 밖에서 열 거라면 꼭 넣으세요 |
| `--device` / `--null-device` | | 서버의 오디오 장치로 트는 존을 붙입니다(`device` 기능으로 빌드) |

## 소리결 DSP

```
원본 → 64비트 → (스테레오) → 볼륨 레벨링 → 샘플레이트 변환 → 헤드룸 → [필터들, 정한 순서대로]
     → 클리핑 측정 → 볼륨 → 장치 형식(64/32비트 부동소수점, 또는 정수 + TPDF 디더)
```

| 단계 | 하는 일 |
| --- | --- |
| 헤드룸 관리 | 체인 맨 앞에 고정. EQ가 올린 만큼 미리 낮춰 클리핑을 막습니다. −3dB에서 시작을 권합니다 |
| 클리핑 표시기 | 0dBFS를 넘은 **곡 안의 시각**을 기록하고, 재생 위치가 그곳을 지날 때 표시등을 켭니다 |
| 볼륨 레벨링 | 자동·트랙·앨범, 목표 −14 LUFS(−16~−23 선택). 올리는 게인은 트루 피크에서 멈추고, 모르는 곡은 −5dB |
| 샘플레이트 변환 | 장치에 맞춤 · 최대 PCM · 호환성 · 사용자 지정. 정밀도(비트)와 통과 대역을 고릅니다 |
| 크로스피드 | bs2b 기본(700Hz 4.5dB) · Chu Moy(700Hz 6dB) · Jan Meier(650Hz 9.5dB) · 사용자 지정 |
| 파라메트릭 EQ | 피크·셸프·로우/하이패스·밴드패스·노치(RBJ). 그래프에서 점을 끌고 휠로 Q |
| 프로시저럴 EQ | 채널별 볼륨·지연·위상 반전·음소거·믹스(행렬)·EQ 밴드를 순서대로 |
| 헤드폰 EQ | AutoEQ/Equalizer APO의 ParametricEQ.txt를 붙여 넣으면 그대로 |
| 컨볼루션 | WAV·FLAC·AIFF 임펄스 응답(모노·스테레오, 30초까지). 블록 1024의 균일 분할 FFT, 지연은 보정 |

"이 기기" 존에서는 레벨링은 곡마다, 헤드룸·필터 체인은 장치 샘플레이트에서 한 번 돌아서 갭리스 이음매에서도
필터 상태가 이어집니다. 설정을 바꾸면 지금 들리는 위치에서 바로 다시 겁니다. "이 브라우저" 존은 엔진이 같은
체인을 거쳐 16/24비트 WAV로 보냅니다.

## 월드: 유튜브와 밴드

아래쪽 탭(넓은 화면은 옆 막대)의 **월드**에는 **유튜브**와 **밴드**(라이브 아카이브)가 있습니다.

유튜브는 유튜브 모바일 앱처럼 씁니다. 구독한 채널의 새 영상(구독 피드), 인기 음악, 검색(동영상·채널·재생목록),
영상 화면(제목, 채널과 구독, 좋아요 수, 설명의 시각을 누르면 그 자리로, 댓글 인기순·최신순, 답글), 채널 화면(배너,
구독자, 동영상, 재생목록), 재생목록 모두 재생. 내 라이브러리 검색에서 찾지 못하면 유튜브 결과가 바로 아래에 뜹니다.
유튜브 링크(영상, 쇼츠, youtu.be, 채널, @핸들, 재생목록)를 검색 칸에 붙여 넣으면 그대로 열립니다.

- **영상은 유튜브 공식 플레이어(IFrame)로 봅니다.** 광고·자막·화질·전체 화면은 유튜브 그대로입니다. 소리는 영상이나
  소리를 받거나 꺼내거나 저장하지 않습니다(유튜브 약관과 API 정책). 그래서 내려받기 단추는 없습니다. 오프라인으로
  보려면 유튜브 프리미엄의 오프라인 저장을 쓰세요. 영상을 틀면 소리의 재생은 멈추고, 소리를 다시 틀면 영상이 멈춥니다.
- **구독은 이 기기에 둡니다.** 채널 화면이나 검색 결과에서 구독을 누르면 됩니다. 유튜브 계정의 구독은
  [구글 테이크아웃](https://takeout.google.com)에서 YouTube → 구독정보만 내보낸 `subscriptions.csv`를 구독 관리에서
  가져옵니다. 구독 피드는 채널마다 유튜브의 공개 RSS로 읽어서 **API 키 없이** 됩니다.
- **검색·댓글·채널 정보·인기 음악은 YouTube Data API v3 키가 있어야 합니다**(무료, 하루 검색 약 100번). Google Cloud
  콘솔에서 YouTube Data API v3를 사용 설정하고 API 키를 만들어 설정 → 연결 → 유튜브(또는 유튜브 화면의 안내)에
  붙여 넣습니다. 키는 이 기기의 데이터 폴더에만 둡니다. 서버 실행 파일은 `SORI_YOUTUBE_KEY`로도 줄 수 있습니다.
  키가 없어도 링크로 연 영상은 제목·채널 이름(oEmbed)과 함께 볼 수 있습니다.
- 안드로이드 앱에서 플레이어의 전체 화면 단추를 누르면 가로 전체 화면이 됩니다(뒤로 가기로 나옵니다). 유튜브·외부
  링크는 앱 밖(유튜브 앱, 기본 브라우저)에서 엽니다.

## 라이브 아카이브

[Live Music Archive](https://archive.org/details/etree)는 녹음을 허락한 밴드의 공연 실황 모음입니다. 검색과 공연
정보는 엔진이 archive.org에 대신 묻고(10–30분 캐시), 곡은 받으면서 풉니다.

- 뒤에서 미리 받고(16MB 앞까지), 멀리 건너뛰면 그 위치부터 범위 요청으로 새로 받고, 연결이 끊기면 받은 데부터
  이어 받습니다. 여는 일·시크는 재생 스레드 밖에서 해서, 네트워크가 느려도 지금 곡과 단추가 멈추지 않습니다.
- 공연마다 가장 좋은 형식만 고릅니다: 24bit FLAC → FLAC → MP3 → Ogg. FLAC은 앞부분만 받아 STREAMINFO로 실제
  샘플레이트·비트 깊이를 신호 경로에 적습니다. 여러 장으로 나뉘어 장마다 트랙 번호를 1부터 다시 센 공연은 파일
  이름 순서로 늘어놓아 장이 뒤섞이지 않습니다.

### 링크로 열기, 라이브러리에 저장

라이브 화면에 archive.org 공연 링크(`archive.org/details/…`, 파일 주소도 됩니다)를 붙여 넣으면 그 공연이 열리고,
**라이브러리에 저장**을 누르면 원본 그대로 음악 폴더에 받습니다.

- **허락한 공연만.** 밴드가 "듣기만" 허락한 공연(stream_only 컬렉션, 원본이 비공개)은 들을 수만 있고 저장 단추
  대신 그 까닭이 보입니다. 라이브 음악 아카이브 밖의 자료는 저작권이 제각각이라 열지 않습니다. 유튜브·타이달 같은
  곳의 링크는 받지 않습니다(저작권, 이용약관, DRM).
- **어디에.** `음악 폴더/Live Archive/<밴드>/<날짜 공연장>/<번호 곡>.flac`. 음악 폴더 바로 아래에 `Music` 폴더가
  있으면 그 아래입니다(휴대폰에서 저장공간 전체를 음악 폴더로 골랐을 때. 안드로이드 11부터 앱은 Music 같은 정해진
  폴더에만 음악 파일을 만들 수 있습니다). 같은 날 같은 곳의 다른 녹음은 `(2)`가 붙은 다른 앨범이 됩니다.
- **원본 그대로, 검사해서.** 받는 동안은 숨은 이름으로 쓰고, archive.org가 알려 준 크기와 SHA-1이 맞아야 제 이름을
  붙입니다. 끊기면 받은 데부터 이어 받습니다. 그다음 라이브러리가 공연 하나를 한 앨범으로 묶도록 태그(제목, 밴드,
  앨범 아티스트, 날짜 공연장, 이어 센 트랙 번호, 날짜)를 적습니다. 녹음한 사람이 적어 둔 다른 태그는 둡니다.
- 한 번에 한 공연씩 차례로 받고(archive.org에 무리를 주지 않게), 다 받으면 라이브러리를 다시 읽어 보관함에
  앨범으로 오릅니다. 취소하면 그 공연에서 받은 것을 지웁니다. 실패한 것은 남겨 두었다가 다시 누르면 이어 받습니다.

## 개발

```bash
node ui/scripts/make-sample-library.mjs     # 시험용 앨범 7장(22곡)을 ./music 에 합성. ffmpeg 필요
(cd ui && npm ci && npx vite build)         # 화면(ui/dist)은 서버 실행 파일 안에 들어간다
cargo run -p sori-server -- --music music   # http://localhost:4380
(cd ui && npx vite)                         # 화면만 고칠 때: /api는 4380으로 넘긴다
cargo test -p sori-core -p sori-server      # 비트 단위 비교는 시험용 라이브러리와 ffmpeg가 있으면 돈다
(cd ui && npm test && npm run typecheck)
```

| 곳 | 무엇 |
| --- | --- |
| `crates/sori-core` | 라이브러리 스캔·태그·표지·검색, 디코딩(DSD 포함), 분석, DSP, 재생 엔진, 라이브 아카이브 |
| `crates/sori-core/src/player` | 렌더 스레드, 링 버퍼, 타임라인, 갭리스, 엔진이 든 대기열, 출력(cpal) |
| `crates/sori-core/src/dsp` | 리샘플러, 바이쿼드, 크로스피드, 컨볼버, 레벨링, 체인, 양자화 |
| `crates/sori-core/src/live` | archive.org 검색·공연, 받으면서 읽는 HTTP 원본 |
| `crates/sori-server` | axum 서버: API, 원본·변환·DSP 스트림, 존 조종(SSE), 잠금, 다른 기기와 잇기 |
| `crates/sori-app` | Tauri 앱(윈도우·안드로이드): 서버를 앱 안에서 띄우고 창을 연다 |
| `ui/` | Vite + React 화면 |
| `ci/` | 안드로이드 프로젝트 손질(권한, 재생 서비스, edge-to-edge), 에뮬레이터 화면 찍기 |

CI(`.github/workflows/build.yml`)는 리눅스에서 시험·린트를 돌리고, 윈도우 설치 파일과 안드로이드 APK를 만들고,
윈도우 러너와 안드로이드 에뮬레이터에서 앱을 띄워 화면을 찍은 뒤, `sori-latest` 미리 보기 릴리스에 올립니다.

### 알려진 한계

- 윈도우 WASAPI 독점(Exclusive) 모드와 DSD 네이티브 출력은 아직 없습니다. "이 기기" 존은 공유 모드로 장치가 받는
  가장 정밀한 형식을 씁니다.
- 안드로이드에서 다른 음악 폴더를 고르는 창이 없습니다(경로를 직접 넣습니다).
- 라이브 아카이브는 개발 환경에서 archive.org에 닿지 않아, 문서화된 응답 형식의 가짜 서버(302, 범위 요청, 끊긴
  연결까지)로 시험했습니다.
- 소리 엔진이 풀지 못하는 형식(돌비 E-AC-3·AC-4, WMA 등)은 그 곡만 기기의 디코더(기본 재생)로 틀고, 다음 곡부터
  다시 엔진으로 돌아옵니다. 이때는 DSP와 갭리스가 빠집니다.
- 룬의 멀티룸, 타이달·코부즈 연동, 헤드폰 프리셋 데이터베이스는 없습니다. 스트리밍 서비스나 유튜브의 음원을
  내려받는 기능은 저작권과 이용약관 때문에 넣지 않습니다. 내려받기는 라이브 음악 아카이브에서 아티스트가 허락한
  공연만 됩니다.
