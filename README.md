# Sori · 소리

내 음악을 **원본 그대로** 스트리밍하는 셀프호스팅 플레이어. 룬(Roon)처럼 표지가 화면의 주인공이고,
음질이 어디서 어떻게 바뀌는지 숨기지 않습니다. 구독료도, 계정도, 광고도 없습니다.

- **비트퍼펙트 전송.** 서버는 디스크의 FLAC·ALAC·WAV·AIFF·MP3 파일을 디코딩도 재압축도 하지 않고 바이트
  그대로 보냅니다. 탐색은 HTTP 범위 요청으로 합니다.
- **소리결 DSP (64비트).** 룬의 MUSE처럼 헤드룸 관리, 샘플레이트 변환(SoX), 볼륨 레벨링(EBU R128), 크로스피드
  (bs2b), 파라메트릭 EQ, 프로시저럴 EQ, 헤드폰 EQ(AutoEQ 붙여넣기), 컨볼루션을 64비트 부동소수점으로 서버에서
  처리하고, TPDF 디더로 24비트까지 줄여 FLAC으로 손실 없이 보냅니다. 프리셋, 필터 순서 바꾸기, 모든 필터 우회,
  클리핑 표시기까지.
- **신호 경로.** 음질 배지를 누르면 원본 → 64비트 변환 → 각 DSP 단계 → 전송 → 브라우저 디코더 → 볼륨 → OS
  믹서까지 단계마다 무엇이 일어나는지 펼쳐집니다. 룬과 같은 네 등급(보라 별 무손실 · 파랑 별 향상 · 초록 점
  고품질 · 노랑 점 저품질)입니다.
- **백그라운드 오디오 분석.** 곡마다 라우드니스·트루 피크·파형을 구해 볼륨 레벨링과 파형 진행 막대에 씁니다.
  분석 전에는 ReplayGain 태그를 씁니다.
- **브라우저가 못 여는 형식도 재생.** ALAC, AIFF, DSD, WavPack, APE는 서버의 ffmpeg가 FLAC으로 바꿔 흘려 보냅니다.
  ALAC→FLAC은 샘플이 그대로라 여전히 무손실입니다.
- **무료·합법 무손실 스트리밍: 라이브 아카이브.** Internet Archive의 Live Music Archive에서 아티스트가 녹음과
  공유를 허락한 공연 실황을 FLAC 원본으로 바로 재생합니다. 키도 가입도 필요 없습니다.
- **룬 같은 화면.** 표지 색에 물드는 앨범·아티스트 화면, 전체 화면 "지금 재생 중", 대기열 패널, Hi-Res 표시,
  장르 모자이크, 파형 시크바, 존 표시, 왼쪽 탐색이 있는 설정, 키보드 단축키, 모바일 화면.
- **끊김 적은 연속 재생과 이어 듣기.** 다음 곡을 미리 받아 두고, 대기열·위치·볼륨을 기기에 저장하며, 운영체제
  미디어 키와 잠금 화면 컨트롤을 지원합니다.

> **왜 "무료 고음질 스트리밍"을 이렇게 만들었나.** 상용 음원을 남의 서버에서 무료로 끌어와 들려주는 서비스는
> 저작권 침해라 만들 수 없습니다. 대신 (1) 이미 가진 음원은 원본 그대로, (2) 공유가 허락된 음원은 무손실로
> — 두 길로 "무료이면서 고음질"을 채웠습니다.

## 바로 해 보기

```bash
npm install
npm run sample        # 시험용 앨범 7장(22곡)을 ./music 에 합성해서 만듭니다. ffmpeg 필요
npm run build
npm start             # http://localhost:3000
```

내 음악을 쓰려면 `MUSIC_DIR`만 가리키면 됩니다. 처음 켤 때 태그와 표지를 읽고, 그다음부터는 바뀐 파일만 다시
읽습니다. 오디오 분석은 그 뒤에 낮은 우선순위로 천천히 돕니다.

```bash
MUSIC_DIR=/Volumes/Music npm start
```

### 설정 (환경변수)

| 변수            | 기본값    | 뜻                                                                         |
| --------------- | --------- | -------------------------------------------------------------------------- |
| `MUSIC_DIR`     | `./music` | 음악 폴더. 읽기만 합니다                                                   |
| `DATA_DIR`      | `./.sori` | 색인, 표지 캐시, 분석 결과, 임펄스 응답. 지워도 다시 만들어집니다          |
| `SORI_PASSWORD` | (없음)    | 넣으면 비밀번호로 잠급니다. 집 밖에서 열 거라면 꼭 넣으세요                |
| `FFMPEG_PATH`   | `ffmpeg`  | 변환·DSP·분석에 씁니다. 없으면 원본 재생만 됩니다                          |
| `PORT`          | `3000`    |                                                                            |

`.env.example`을 `.env.local`로 복사해 써도 됩니다. 화면 취향, 재생 동작, DSP 설정은 브라우저(존)마다
저장되고, 분석 속도는 **설정 → 라이브러리**에서 바꿉니다.

### 도커

```bash
docker compose up -d          # docker-compose.yml의 ./music 을 내 음악 폴더로 바꾸세요
```

이미지에는 ffmpeg(SoX·bs2b 포함)가 들어 있습니다. 음악 폴더는 읽기 전용으로 붙이고, 색인과 표지는 `sori-data`
볼륨에 남습니다.

## 소리결 DSP

룬이 DSP를 기기가 아니라 Core에서 돌리듯, Sori도 서버의 ffmpeg 한 번으로 체인 전체를 처리합니다. 아무것도 켜지
않으면 이 길을 타지 않고 원본 바이트가 그대로 갑니다.

```
원본 → 64비트 부동소수점 → 볼륨 레벨링 → 헤드룸 → [필터들, 정한 순서대로] → 샘플레이트 변환
     → 64비트 → 24비트(TPDF 디더) → FLAC 무손실 전송 → 브라우저
```

| 단계 | 하는 일 |
| --- | --- |
| 헤드룸 관리 | 체인 맨 앞에 고정. EQ가 올린 만큼 미리 낮춰 클리핑을 막습니다. −3dB에서 시작을 권합니다 |
| 클리핑 표시기 | 서버가 0dBFS를 넘은 **곡 안의 시각**을 기록하고, 재생 위치가 그곳을 지날 때 표시등을 켭니다 |
| 볼륨 레벨링 | 자동·트랙·앨범, 목표 −14 LUFS(−16~−23 선택). 올리는 게인은 트루 피크에서 멈추고, 모르는 곡은 −5dB |
| 샘플레이트 변환 | 출력 장치에 맞춤 · 최대 PCM(2의 거듭제곱) · 호환성 전용 · 사용자 지정. SoX 20/28/33비트, 정밀·부드럽게 |
| 크로스피드 | bs2b 기본(700Hz 4.5dB) · Chu Moy(700Hz 6dB) · Jan Meier(650Hz 9.5dB) · 사용자 지정 |
| 파라메트릭 EQ | 피크·셸프·로우/하이패스·밴드패스·노치. 그래프에서 점을 끌고 휠로 Q. 여러 개 둘 수 있습니다 |
| 프로시저럴 EQ | 채널별 볼륨·지연·위상 반전·음소거·믹스(행렬)·EQ 밴드를 순서대로 |
| 헤드폰 EQ | AutoEQ/Equalizer APO의 ParametricEQ.txt를 붙여 넣으면 그대로 |
| 컨볼루션 | WAV·FLAC·AIFF 임펄스 응답(모노·스테레오, 30초까지)을 올려 적용. 샘플레이트가 다르면 SoX로 맞춤 |

화면의 EQ 곡선은 서버가 거는 필터와 같은 RBJ 공식으로 그리며, 테스트가 실제 ffmpeg 출력과 0.05dB 안에서
맞는지 잽니다. 설정을 바꾸면 지금 위치에서 스트림을 다시 걸기 때문에 아주 잠깐 끊깁니다.

## 음질 이야기

### 무엇이 "원본 그대로"인가

DSP를 끈 상태의 서버 → 브라우저 구간은 비트퍼펙트입니다. `/api/stream/<id>`가 보내는 바이트는 파일과 똑같고,
테스트가 이를 확인합니다. 그 뒤는 브라우저와 운영체제의 몫이라, 룬이 "System Output"을 그렇게 표시하듯 신호
경로의 마지막 단계(OS 믹서)는 늘 **고품질**입니다.

- **브라우저 디코더**는 FLAC을 32비트 부동소수점으로 풉니다. 24비트까지는 손실이 없습니다.
- **볼륨**을 100% 아래로 내리면 디지털 볼륨이라 신호 경로에 **향상** 단계로 나타납니다. 앰프나 DAC에서 볼륨을
  조절하고 Sori는 0dB에 두면 이 단계가 빠집니다.
- **출력 장치**의 샘플레이트가 곡과 다르면 브라우저가 리샘플링합니다. DSP의 샘플레이트 변환을 "출력 장치에
  맞춤"으로 켜면 서버의 SoX가 대신, 더 정밀하게 바꿉니다.

### 형식별로 어떻게 재생되나

| 형식                | 크롬·엣지      | 사파리         | 파이어폭스     |
| ------------------- | -------------- | -------------- | -------------- |
| FLAC, WAV, MP3, AAC | 원본 그대로    | 원본 그대로    | 원본 그대로    |
| ALAC                | FLAC으로 변환  | 원본 그대로    | FLAC으로 변환  |
| AIFF                | FLAC으로 변환  | 원본 그대로    | FLAC으로 변환  |
| DSD, WavPack, APE   | FLAC으로 변환  | FLAC으로 변환  | FLAC으로 변환  |

어느 쪽인지는 브라우저에 직접 물어서(`canPlayType`) 정합니다. **설정 → 오디오**에 지금 브라우저의 표와 서버의
처리 능력(SoX, bs2b, afir, ebur128)이 나옵니다.

## 라이브 아카이브

[Live Music Archive](https://archive.org/details/etree)는 녹음을 허락한 밴드(테이퍼 친화 밴드)의 공연 실황 모음입니다.
Sori는 검색과 공연 정보를 archive.org API로 가져오고, 음원은 브라우저가 archive.org에서 직접 받습니다. DSP를
켜면 서버가 받아 같은 체인에 태웁니다.

- 공연마다 가장 좋은 형식만 고릅니다: 24bit FLAC → FLAC → MP3 → Ogg.
- archive.org는 FLAC의 샘플레이트를 알려 주지 않습니다. 재생을 시작하면 서버가 파일 앞부분만 받아 FLAC 헤더
  (STREAMINFO)를 읽고, 신호 경로에 실제 값을 적습니다.
- 비공개(스트리밍 전용) 파일은 건너뜁니다. 공유 조건은 각 공연 페이지를 따릅니다.

서버가 인터넷에 나갈 수 없으면 이 화면만 안내 문구를 띄우고, 내 라이브러리는 그대로 동작합니다.

### 알려진 한계

- 브라우저 재생이라 출력 장치를 독점(Exclusive/Hog) 모드로 열 수 없습니다. 그래서 신호 경로의 마지막은 늘 OS
  믹서(고품질)입니다.
- 샘플레이트 변환 필터는 선형 위상만 있습니다. ffmpeg가 SoX의 위상 설정을 열어 두지 않아, 룬의 최소 위상
  필터는 아직 없습니다. DSD 출력(재변조)도 없습니다.
- DSP 설정을 바꾸면 스트림을 다시 거느라 잠깐 끊깁니다.
- 곡 사이 전환은 미리 받아 둔 오디오 요소로 바꿔 타는 방식이라 거의 이어지지만, 샘플 단위 갭리스는 아닙니다.
- 룬의 멀티룸, 타이달·코부즈 연동, 헤드폰 프리셋 데이터베이스(OPRA)는 없습니다. 헤드폰 EQ는 AutoEQ 값을 붙여
  넣어 씁니다.
- 라이브 아카이브의 실제 응답과 DSP 경로는 archive.org에 닿지 않는 환경에서 만들어, 문서화된 응답 형식으로만
  시험했습니다.
- 도커 이미지는 빌드해 보지 못했습니다(빌드 환경이 Debian 저장소에 닿지 않음). 이미지 안에서 실행되는
  standalone 서버(`SORI_STANDALONE=1 npm run build` → `node .next/standalone/server.js`)는 직접 확인했습니다.
